# Faces read path out of PHP (design, 2026-11-05)

## Why

Measured with `tools/bench_faces.py` (tangui: 705 listed clusters, 1,343-photo largest cluster):

| step | today | cause |
|---|---|---|
| overview list PROPFIND | 4.7 s | `nc:nbItems` costs 4.2 s: one count query per cluster; any Nextcloud request is ~0.3 s of PHP bootstrap |
| 705 covers | 63 MB, 6 s warm / 16 s cold | a full-photo 1024 px preview through the PHP preview stack, cropped in CSS |
| largest cluster PROPFIND | 0.36 s, 2.5 MB | DAV XML + Sabre |

Goal: Faces reads are bounded by MySQL and disk, not PHP. Writes (rename, merge,
remove a face) stay on the existing DAV endpoints for now.

## Pieces

### A. Face crops on disk (daemon)

- At detection time the face worker already holds the decoded image. For each face it
  writes a 256x256 JPEG (quality ~82) of the box expanded 1.6x around its centre,
  clamped to the image, then rotated to display orientation by the photo's EXIF
  orientation (detection runs on raw pixels; the stored box stays in raw coordinates).
- Path: `<crop_root>/<user_id>/<detection_id>.jpg`, `crop_root` =
  `/var/lib/nextcloud/recognize-faces` (outside the data dir so Nextcloud never scans it;
  default SELinux label there is httpd_sys_rw_content_t). Written to a temp file in the same
  directory, then `os.replace`. Owner apache, files 0640, dirs 0750.
- Detection ids come from PHP: `InternalController::results` returns the inserted ids in
  input order (`{"status":"ok","detection_ids":[...]}`); when it keeps existing detections
  it returns `[]` and the backfill covers them.
- Backfill + cleanup in the daemon's idle time (no pending work): a bounded batch per idle
  tick creates missing crops for existing detections and deletes crop files whose detection
  no longer exists. Skips detections with an empty user_id.

### B. Read API in Python + signed crop links in nginx

- `python/api_server.py`, its own systemd unit `recognize-api.service` (User=apache),
  stdlib `ThreadingHTTPServer` on `127.0.0.1:8291`, one DB connection per thread through
  `python/db.py`. No new dependencies.
- nginx (inside the Nextcloud server block, via one `include /etc/nginx/recognize/*.conf;`):
  - `location ^~ /recognize-api/ { proxy_pass http://127.0.0.1:8291/; }`
  - `location ^~ /recognize-faces/ { secure_link $arg_md5,$arg_expires;
     secure_link_md5 "$secure_link_expires$uri <crop_link_secret>"; ...; alias <crop_root>/; }`
    -> 403 on a bad signature, 410 when expired. Links expire on an hourly boundary + 6 h so
    the browser cache hits across page loads.
- Auth: `Authorization: Bearer <token>`, token = `b64url(json{"v":1,"uid","exp"}) "." b64url(HMAC-SHA256(api_token_secret, payload))`,
  compared in constant time; exp <= 1 h. PHP mints it: `GET /apps/recognize/api/v1/faces-token`
  (logged-in user only, no admin needed) -> `{token, expires}`.
- Secrets: `api_token_secret` (PHP appconfig, sensitive + nc_config.json) and
  `crop_link_secret` (nc_config.json + the root-owned nginx snippet). Generated by
  setup_config.py; nginx snippet written by deploy.sh.
- Endpoints (JSON, `Cache-Control: private, no-store`); every query filters on the token's uid,
  parameterised SQL only, only files under the owner's `files/` (not trash):
  - `GET /v1/clusters?min=5` -> `[{id, title, count, cover}]` (`cover` = signed crop URL of the
    cluster's best detection with a crop, largest box first; null if none).
  - `GET /v1/clusters/<id>?offset&limit` -> `{id, title, count, files: [{fileid, path, name, mime,
    etag, mtime, size, detection: {id, x, y, width, height, crop}}]}`; 404 if not the user's.
  - `GET /v1/search?q=` -> clusters whose title contains q (LIKE with escaped wildcards).
  - `GET /v1/health`.

### C. Photos frontend (after B is live)

The overview and the cluster view read from `/recognize-api/v1`, covers are plain `<img>` on the
signed crop URL (no transform maths); a name filter on the overview. Falls back to the DAV
path if the API fails. Writes unchanged.

### D. Measure

`tools/bench_faces.py --api python` replays C's requests, compared with `--compare` against the
DAV baselines in `bench-results/`.

## Out of scope for now

Grid thumbnails of a cluster's photos (Nextcloud previews, ~85 ms each), the EXIF fix in
detection itself (needs re-detection and name-preserving re-clustering), writes.
